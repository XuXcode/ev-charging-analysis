# 自定义地点驾车可达性

## 数据与交互

现有可达性页提供“区县统计 / 自定义地点分析”，不新增路由。区县统计继续读取既有代表点快照；自定义模式拥有独立起点、候选和路线状态，不受区县筛选影响，也不写入 RoadAccessibilityRun。

起点为GCJ-02坐标，须位于现有14市州真实行政边界范围内。候选来自ChargingStation与PoiQuality联查，仅使用source=amap、classification=public_candidate的真实POI。先用20km包围盒与球面距离筛选最近3/5个站点，再请求道路；候选最近不保证道路全库最快。

高德V3驾车结果的steps.polyline逐段绘制蓝色轨迹，不跨缺失路段连接直线。无轨迹、无路线、权限失败、超额均明确显示缺失，不补造结果。默认选择已解析路线中时间最短者；点击其他候选只更新高亮，不改变相机；“查看全部路线”为显式视角操作。清除恢复选点前视角。5/10/15分钟标签是单起点到候选站点的阈值判断，不是等时圈、人口或面积覆盖率。

## 接口

基路径 `/api/v1/analysis/accessibility/custom`，响应复用 `APIResponse` 包装。

- `GET /policy`：开关、今日请求计数及无每日上限标记；不请求高德。
- `POST /plan`：起点校验、真实候选、缓存命中、requiredCalls、planId；不请求高德。
- `POST /routes`：参数origin={longitude,latitude,name}、candidate_count=3或5、max_api_calls=0至5、plan_id。默认0只用缓存；大于0需与最新planId匹配且上限足够，否则不调用高德。
- `GET /places?keyword=...`：高德输入提示，仅返回有坐标的地点。搜索按钮和可选650ms防抖自动补全共用接口。地点缓存6小时。

## 调用安全与缓存

Web Service Key仅在后端。`CUSTOM_ACCESSIBILITY_ENABLED`默认false；启用前人工检查高德账号控制台免费配额和服务授权。项目不设本地每日调用次数上限，已移除CUSTOM_DRIVING_DAILY_LIMIT与CUSTOM_PLACES_DAILY_LIMIT配置；高德账号自身的配额和计费规则仍然有效。页面在新增道路请求前确认数量。当前部署无账号权限系统，公开部署应在反向代理加入访问控制及请求限流，不能将单次查询确认当作完整的公共服务防滥用方案。

跨进程使用MySQL GET_LOCK串行协调交互请求，在请求发出前将已用次数、最近调用时间写入既有RoadODCache独立命名空间，UTC日切换。相邻同类请求至少1.05秒，不自动重试；失败和超时也记录次数。道路批次最多5次，并受显式max_api_calls的单次确认范围限制，不设每日次数拦截。高德拒绝服务后停止剩余请求。

道路缓存沿用已有endpoint+GCJ-02+规范化参数摘要与7日TTL。旧记录只有时间/距离没有轨迹时不视为可绘制缓存，确认后补查并丰富同一OD记录；不会改写区县历史快照。地点提示和请求计数记录使用不同摘要命名空间，无表结构迁移。查询坐标和缓存存储于现有数据库，不将Key、完整provider请求URL或第三方错误正文写入响应。

## 本轮人工验收（2026-10-17）

用户确认免费配额后，将本地验收上限设为驾车3次、地点提示1次。以长沙火车站地点提示结果为起点，取得3条真实驾车路线，按时间排序为63秒/160米、440秒/1,015米、508秒/1,665米，均包含道路轨迹。随后重复查询命中3条OD缓存、新增请求0；五站模式显示3条缓存及2条未查询候选，预算不足时不额外调用。

已在实际浏览器人工检查地点搜索、地图选点、三/五候选切换、蓝色路线、候选高亮、拖动缩放、清除恢复视角及切回原122区县统计。没有执行自动化测试、没有新增测试文件。未验收完整五条新增道路请求，以遵守本轮最多3次的授权。

后续按用户要求已取消本地每日次数上限，并清除本地及示例环境中的3/1限制；上述3次道路、1次地点提示为历史验收的实际请求数。仍保留限速、缓存、失败不重试和单次道路查询确认，不会因修改上限而自动请求高德或进行充值。
