## 边界与坐标

现有湖南 GeoJSON 含 14 个唯一市州编码、7,528 个顶点，未发现不闭合环或无效坐标。与 [DataV.GeoAtlas 湖南市州边界](https://geo.datav.aliyun.com/areas_v3/bound/430000_full.json) 对照后，规范化 JSON 内容一致，SHA-256 为：

```text
a010692a27bf9fa1a6ba53067b78040d0e6b734929175bf35abc4e54834a9f48
```

[DataV 地图数据格式文档](https://help.aliyun.com/en/datav/datav-7-0/user-guide/map-data-format-1) 与 [高德 JS API 坐标说明](https://developer.amap.com/api/javascript-api-v2/guide/abc/basetype) 是 GCJ-02 展示口径依据。后续接入 WGS84 数据前需要明确转换规则，不能仅因文件是 GeoJSON 就认定是 WGS84。

入库样本在经度 108–115、纬度 24–31 的宽泛合理性范围内未发现异常。这只是粗筛，不证明每个 POI 都位于标注市州或区县内。本轮未做逐点行政区归属判断、实地坐标配准或真实营业核验。

## 重复执行

在项目根目录、现有 MySQL 已启动且 `backend/.env` 数据库配置有效时运行：

```powershell
.\backend\.conda\python.exe scripts/audit-poi-quality.py --verify-boundary-source
npm.cmd run check:quality
npm.cmd run build
```

脚本使用现有 Conda 环境和配置，只执行查询，MySQL 显式只读事务；边界来源检查只下载公开 JSON 作比较，不替换已有边界。无需新增后端接口，也无需重新采集。

输出 `public/data-quality/poi-audit.json` 离线快照和上述 CSV。页面仅在快照的批次 ID、样本数量和更新时间都与真实接口匹配时展示核验数量；旧快照不冒充当前核验结果。重新生成后应刷新开发页面，发布环境需重新构建。

名称提示规则集中在 `src/config/poi-quality-rules.json`。站点信息窗展示命中的名称线索，同时明确“营业状态尚未核验”。本轮没有实现可达性、供需、选址优化或 AI。
