# 需求、低可达性与选址基座

本轮在已有 Vue3 + FastAPI + MySQL 上增量实现，不替换采集器、站点接口或道路任务。新增接口只读现有道路缓存，**不会发起高德路线请求**。真实需求和新建候选设施尚未导入，因此当前没有湖南实际新增站点方案，也不展示虚构收益。

## 真实输入与接口

前端“布局优化”支持选择市州/区县、导入真实 JSON、选择数据集、配置六类需求权重、新增预算 N、Greedy/MCLP、米或秒阈值。没有完整输入时禁用计算。切换参数会清除旧结果，防止旧方案被误认为新方案。

所有接口位于 `/api/v1/analysis/planning`：

| 方法 / 路径            | 用途                                                     |
| ---------------------- | -------------------------------------------------------- |
| POST `/datasets`       | 导入需求、候选或容量证据；重复内容复用数据集             |
| GET `/datasets`        | 数据集与批次目录                                         |
| POST `/demand-preview` | 标准化、权重、有效节点及缺失预览                         |
| POST `/od-estimate`    | 根据区域和筛选约束估算候选矩阵及现状近邻基线，不请求路线 |
| POST `/optimization`   | 完整输入求解并持久化方案；道路缓存不完整返回 409         |
| GET `/runs/{id}`       | 读取冻结方案及追溯信息                                   |

数据文件顶层字段：`kind`（demand/candidates/capacity）、`name`、`batch`、`coordinateSystem`（只接受 GCJ-02）、`records`。每条记录必须有 `id`、`name`、`position:[经度,纬度]`、`adcode`、`source`、`sourceUrl`、`year`、`unit`。候选还必须有真实 `poiId` 与 `category`（parking/commercial/office/transport/residential）。需要转换的坐标应在独立预处理阶段转换并保留原始证据，不直接把 WGS84 声明成 GCJ-02。

需求 `variables` 支持 population、residential、parking、commercial、office、transport；值必须非负，缺失为 null。一个批次应采用一致统计时点、空间粒度和变量单位；混合单位需拆批并保留定义。来源字段是提交者的证据声明，格式校验不等于独立核实真实性。未导入真实数据前，不填示范坐标或业务数字。

服务能力可选 `station_capacity`（服务能力定义须在来源中说明）、`charger_count`（个）、`power`（kW）、`waiting_time`（分钟），缺失保持 null。当前仅保存字段，不计算排队、容量可达性或将其写入现有 ChargingStation 统计。

第一版同步求解限制为每批最多 500 需求点、300 候选设施；N 为不超过可用候选数的新增预算上限，允许零新增。超限先按行政区域拆批。

## 标准化、筛选与算法口径

需求采用 min-max 标准化，正权重归一化后加权求和。启用变量缺失或变量在本区域无区分度时，节点权重保持未知并拒绝优化；零观测与缺失分开。结果是配置的需求权重指数，**不是充电需求量、人口或面积**。

候选只保留导入的真实设施位置；按来源/POI ID、空间近邻去重，限制在所选边界内，默认距现有站至少 100m，候选去重距离 20m。评分框架仅接受有来源的标准化证据，缺失不填分；当前优化按增量覆盖选择，不使用没有证据的综合分。候选尚未经土地、许可、电力接入与经营条件审查，推荐不能解释为可直接施工点。

Greedy 每轮选择新增覆盖需求权重最大的候选；同分按 ID，零收益时停止，明确标记为启发式。

MCLP 使用二元选址变量 x 和新增覆盖变量 y：最大化 `Σ w_i*y_i`，约束 `Σ x_j ≤ N`、`y_i ≤ Σ a_ij*x_j`。已被原有站覆盖的节点不重复计收益。求解状态区分最优和限时可行解，输出 gap；无可行解不生成结果。覆盖目标不保证平均出行时间最优。

距离口径是 GCJ-02 球面直线距离近似；道路口径使用完整真实缓存。候选完整 OD 矩阵的未知边不能当作不可达；现状基线只考虑每个起点 20km 内空间最近 3 个公共候选站，不能宣称全站道路最短。平均时间只对成功路线起点求均值，显示有效起点数；缺失不补零。

固定测试输入有 6 个等权需求点、3 个候选、N=2：Greedy 覆盖 5 个，MCLP 覆盖 6 个；反转输入顺序和重跑结果保持一致。该用例仅存在于隔离测试数据库，**不是湖南实际优化结果**。距离方案和完整缓存道路方案均验证 MySQL 冻结输入重放：

```powershell
cd backend
python -m app.services.analysis.planning_replay --run-id <方案ID>
```

重放只用冻结证据、不读最新 POI、不调用高德。锁定环境用于复现；不同求解器版本或限时条件可能改变同目标的候选组合，重放会报告差异。

## 低可达性页面

保留 122 区县内部代表点原有道路观测；当前全省 15 分钟阈值下 39 个代表点超过阈值。页面支持 5/10/15 分钟切换、区县清单排序、点击后切换对应高德实景地图及真实入库站点。只称“低可达性代表点”，不称人口/面积覆盖率，也不称“高需求低供给”。原始方法及限制见 [道路说明](ROAD_ACCESSIBILITY.md)。

## 当前缺口与下一步

缺少真实需求观测（尤其一致粒度的人口/居民区等）、新建候选设施批次、需求到候选完整道路矩阵、真实桩数/功率/服务容量/等待时间和建设可行性约束。下一步先导入一个市州的小规模真实需求及停车场/交通节点候选，核实统计粒度和来源，再看调用估算并单独确认道路采样预算；有完整数据后运行并复核首个真实方案。不得把现有充电站当作新建候选补满结果。
